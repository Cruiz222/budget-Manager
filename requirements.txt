# Passwords. A runtime dependency and not a development one: without it the
# application can start, serve, and answer /health, and no account on it can ever
# log in - ``Argon2PasswordHasher`` is the only adapter for the ``PasswordHasher``
# port, and the composition root builds it. Nothing in the domain imports it,
# which is why the whole of Phase 2a's domain half was written and reasoned about
# before this line existed.
#
# Pinned to the version pip resolved on 2026-09-12, rather than to one chosen from
# the changelog. Which version is right is a question about a hash format, not
# about a preference: an encoded hash records the parameters it was made with, so
# a version bump can only ever be *additive* to the hashes already in the
# database - every old password keeps verifying against the parameters it was
# written with. That is why this pin is safe to raise later and why raising it is
# a deliberate act rather than a routine bump.
#
# What does *not* exist yet, and is worth knowing before relying on the paragraph
# above: nothing re-hashes an old password when its parameters fall behind
# ``argon2-cffi``'s defaults. ``PasswordHasher`` has ``hash`` and ``verify`` and no
# third method, so the cost can be raised safely but the existing rows will not
# move to the new one on their own. That is a real feature - re-hash on the next
# successful login, which is the only moment the plaintext is in hand - and it is
# deliberately not in Phase 2a, which is why it is written here rather than
# assumed. Left unsaid, "the parameters are in the hash" reads as though the
# migration were already handled.
#
# ``argon2-cffi-bindings`` is deliberately *not* listed. It is a transitive
# dependency of the line below - pip resolved 26.1.0 alongside it - and pinning a
# package this file does not choose by hand would be describing an environment
# rather than declaring one. This file says what we depend on; ``pip freeze`` says
# what that resolved to.
argon2-cffi==25.1.0

# Talking to the payment provider. A runtime dependency since Phase 3, and it was
# a development one before that - it is the same pinned version, moved rather
# than added.
#
# It used to be here because starlette's ``TestClient`` is built on it, and the
# comment above it said "Nothing shipped imports it". That sentence is now false:
# ``PaystackPaymentProvider`` posts a JSON body to open a collection, and that is
# the only place in the shipped code that touches a network at all. Worth naming
# the change rather than leaving a stale comment, because the *reason* moved with
# the line - before, httpx was a test tool by accident of what the framework
# used; now it is what a real request a real person made depends on.
#
# Note what did **not** need it: the webhook's signature check is HMAC-SHA512
# over the body, which is stdlib ``hmac`` and hashlib. The half of this
# integration that decides whether money is credited has no third-party
# dependency in it at all.
httpx==0.28.1

# Verifying a Google sign-in. A runtime dependency since Phase 2c, and the first
# line in this file that is a **deliberate departure from the stdlib streak** -
# which is why the paragraph above is the right place to start reading it.
#
# That paragraph says the webhook's half of the Paystack integration "has no
# third-party dependency in it at all", and it is true because the standard
# library *has* HMAC. This is the same instinct one step further along, and it is
# where the instinct stops being a virtue: stdlib has no RSA, so checking a Google
# signature without a library means implementing PKCS#1 v1.5 verification by hand
# around a public key parsed from a JWKS document. That is not a smaller
# dependency, it is a hand-rolled one - and the failure mode of getting it subtly
# wrong is that forged tokens verify. So the streak is honoured where it can be
# and broken here, in the open, rather than bent to look unbroken.
#
# Only the *extra* is needed for verification: ``PyJWT`` alone signs and decodes
# HMAC and leaves RS256 unavailable, so ``crypto`` is what brings
# ``cryptography`` in and what makes ``algorithms=["RS256"]`` mean anything. The
# adapter is the only thing that imports either, so nothing in the domain or the
# application layer has heard of this line - the same shape the argon2 paragraph
# above describes, and for the same reason.
#
# **No client secret comes with it, and that is a property of the flow rather
# than an omission.** Nothing here exchanges an authorization code, so there is no
# secret to hold and none to configure; the only setting this feature adds is a
# client id. That is what makes this flow cheaper to run than the redirect one, and
# it is also the half that is deliberately deferred to Phase 4 - see the README.
#
# **Confirm the number below on the first install.** It is pinned the way the rest
# of this file is, but the pin was written without a ``pip`` run available in the
# environment that authored it, which is the one thing this file's convention
# cannot supply from memory: every other line here records what pip actually
# resolved, and this one records what it is expected to. An install that disagrees
# is telling you the number, not breaking anything.
PyJWT[crypto]==2.10.1

# Rendering the browser client's pages. A runtime dependency since checklist item
# i19 landed, and the third departure from the stdlib - but the argument is
# different in kind from the two above, so it gets a different paragraph rather
# than a longer version of theirs.
#
# httpx and PyJWT are *capability* departures: httpx does something the standard
# library has no HTTP client for, and PyJWT does RSA. This one is a departure of
# degree, and it is worth saying plainly rather than dressing up: the stdlib has
# ``string.Template``, and it could have rendered every page this repository
# ships. What it does not have is **autoescaping**, and that is the whole of why
# this line exists.
#
# Every page here prints a value somebody else supplied - the address an account
# signed up with, the prose of a refusal, a wallet's balance parsed back out of
# a submitted form. An interpolator that writes those into HTML unescaped is a
# cross-site scripting hole in the one place this system's credential lives: the
# session cookie is ``HttpOnly``, so a script injected into a page cannot read it
# - and it does not need to, because it can post the withdrawal form on the
# visitor's behalf instead. Jinja2 escapes by default, which makes the dangerous
# thing (``|safe``) the one a person has to ask for, and no template in this
# repository asks.
#
# So the standard this file holds its departures to is met, and slightly
# differently: ``string.Template`` would be fewer lines today, and a reachable
# hole the first time somebody signs up with an apostrophe in their name.
#
# **Confirm the number below on the first install**, for the reason the PyJWT
# paragraph above gives - it was pinned without a ``pip`` run behind it, so it
# records the expected resolution rather than an observed one. Unlike PyJWT's,
# this one is a mature package whose 3.1 line has been current for years, so a
# discrepancy is more likely to be a newer patch than a wrong guess.
Jinja2==3.1.6

# Reading the browser client's form posts. A runtime dependency since i19, and it
# is the only line in this file that adds **no capability of ours at all** - which
# is exactly why it needs the paragraph, because it is the line most likely to
# look deletable.
#
# It is not, and the reason is a rule inside starlette rather than a feature this
# repository uses. ``request.form()`` parses an ``application/x-www-form-urlencoded``
# body, and starlette's implementation checks whether this package can be imported
# *before* it looks at the request at all: with it absent, the call raises rather
# than returning an empty form. So the choice is not "parse forms with this or
# without it" - it is "declare it, or write a parser by hand", and a hand-rolled
# one is the thing the PyJWT paragraph refuses in the same words: a subtly wrong
# parser is a place where two fields can be made to disagree with what the server
# believes they are.
#
# Nothing in this repository imports it and nothing ever will. That is the point:
# it satisfies starlette's import check and then gets out of the way.
#
# **Confirm this number on the first install too**, for the reason given twice
# above. This one is the least predictable pin in the file - the package's version
# sits in a long ``0.x`` line, where every release is nominally allowed to change
# anything, and the number below is the one expected rather than the one seen.
python-multipart==0.0.20
